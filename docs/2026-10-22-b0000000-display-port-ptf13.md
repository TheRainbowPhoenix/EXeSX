# DY357 external parallel display bus at 0xB0000000 — original BIOS evidence

**22 October 2026.** Private reference: checksum-verified user-owned `OSUP.BIN` (SHA-256 `d5791bec1c7739315fb6113b5d6890a21f6c454fcf7a05a0381cfaaa70808fb0`) and extracted two-PT_LOAD A7-only ELF, BIOS at 0x60000000. Only addresses, opcodes' semantics and public documentation are included here, never raw ROM/pixels/media.

## 1. Strong command-level identification: a DBI/8080-style TFT LCD controller

The BIOS's `0x60015248` routine emits **halfword writes to the constant address `0xB0000000`**, in exactly this order:

- `0x2A` followed by two big-endian 16-bit column coordinates (four eight-bit parameter values), derived from R0 and R1
- `0x2B` followed by two big-endian 16-bit row coordinates, derived from R2 and R3
- `0x2C` to begin a streaming pixel-memory write

The caller at `0x600154B8` then streams repeated `STRH` samples from a RAM image through that **same address**. `0x60015540` emits `0x2A/0x2B/0x2C` for a small fixed-color fill. Orientation helper `0x60015328` emits `0x36` followed by either `0x40` or `0x60`; `0x600153D0` sends `0xB2` followed by configuration bytes. Decoder `0x60015104` also emits `0xB2` and certain special values using a 16-bit stream parser.

These command semantics are characteristic of **MIPI Display Command Set / DBI parallel TFT panels**. The command sequence is a strong match for ST7789-family controllers, in which `B2` is `PORCTRL` (porch timing); other panels such as ILI9341 share `2A/2B/2C/36`, and ILI9341 also uses `B2` with a different meaning. This code **does not uniquely identify the controller vendor/model**. Confirm against panel markings, full init register list, and any ID-read commands before implementing vendor-specific behavior. References: [ST7789 commands in RIOT-OS](https://api.riot-os.org/st7789__internal_8h.html), [ST7789 command table](https://github.com/mireq/st7789-stm32-driver/blob/master/lib/st7789.h), [ILI9341 DBI window-setting implementation](https://github.com/notro/fbtft/blob/master/fb_ili9341.c).

## 2. Separate external bus control registers, not eMMC flash

In these same functions the BIOS writes **`0x00010000`** to two word locations **`0x44F00000` and `0x44F00004`**, alternating around the 16-bit stream to `0xB0000000`, including ARM barrier instructions. The two addresses appear to control **external bus handshaking / register select / output enable** while a parallel LCD DBI command or pixel-data cycle is issued. Their exact electrical meaning (D/C, CS, WR, timing or switch) is *not proven*. The `0x44F00000` source is separate from the i.MX7ULP on-chip FlexBus controller's MMIO at **`0x40100000`** and separate from external chip select memory `0xB0000000`. A basic anonymous RAM mapping at either address cannot reproduce a panel's command decoder.

**Read behavior:** The analyzed `0x60015104..0x60015600` stream path writes the external LCD port with `STRH` and does **not** issue `LDRH` from `0xB0000000`. No authentic LCD-ID or status response has yet been observed in this specific path. Do not invent a readback value or assert the panel is write-only globally.

## 3. Current boot stop: PTF13 high then low

The later original A7 boot routine `0x601B40CC` processes real DMA completion, calls the orientation helper and the display-window setup, then directly polls **GPIOF.PDIR at `0x400F00D0`**, bit `0x2000` (PTF13), in two consecutive loops:

```text
0x601B4144–0x601B414C: wait until GPIOF13 HIGH
0x601B4150–0x601B4158: wait until GPIOF13 LOW
```

This is **edge synchronization**, not a normal read of LCD command data. A likely explanation is the external LCD's **TE/tearing-effect synchronization output** (frame/scan synchronization), but the pin mux and board wiring are still unknown. TE is a testable **hypothesis**, not a proven DY357 signal name. The original pin input was low in the private synthetic-controller run, so the first edge cannot occur. A static high or low will not satisfy both loops; arbitrary instant toggling would hide missing electronics.

The PTF13 input and the external display interface are not independent proof of the actual physical chip model. Need cross-reference original Port F PCR13 setup and pin electrical mode with complete display init commands. A screenshot or panel part number would help externally but is not necessary to continue firmware-level analysis.

2. Identify FlexBus CS configuration at `0x40100000`, and Port F PCR13 mux/interrupt/direction before naming PTF13 TE. Inspect panel datasheet/physical chip marking for a definitive controller ID.
3. **Only after confirming the wiring:** implement an opt-in 16-bit LCD DBI command/pixel device for real column/page/RAMWR/MADCTL operations, a stateful rectangle/framebuffer, and a virtual-clock periodic TE signal wired to GPIOF13 with configurable phase/period grounded in LCD timing; preserve negative cases (panel absent, TE disabled, static pin).
