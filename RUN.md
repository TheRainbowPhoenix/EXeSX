# RUN — EXeSX DY357/XD-SX9850 experimental emulator

This guide applies to the `experiment/dy357-m4-inputs-0804-20261023` branch. The emulator runs the **original, unchanged** A7 and M4 firmware on an experimental i.MX7ULP/QEMU machine. A displayed factory menu is not evidence that all peripherals or tests pass.

**Latest tested binary at writing:** Linux x86-64 build from [CI run 40790695246](https://github.com/TheRainbowPhoenix/EXeSX/actions/runs/40790695246), repository revision `937b2ea5c26a780c4edefdad2d9a904725b6a1dd`, QEMU source snapshot `26e8a4c3306806e55e1dab7559eada5486bfd540`. [Windows CI](https://github.com/TheRainbowPhoenix/EXeSX/actions/runs/40790695077) passed for the same revision. Recheck the branch's Actions builds for newer changes. These are **experimental test artifacts**, not official Casio/QEMU releases.

## Files you need

| File | Source | Required? |
|---|---|---|
| `qemu/qemu-system-arm` and `qemu/lib/*` | Extract the **entire** passing Linux CI binary bundle `exesx-qemu-linux-x86_64.tar.gz` into a directory named `qemu` | Yes |
| `qemu/factory_control_panel.py`, `qemu/lcd_qmp.py`, `qemu/profiles/imx7ulp-early-boot.ini` | Same binary bundle (or matching source checkout `scripts/`, `profiles/`) | Yes for factory UI |
| `a7-bios-os.elf` | Extracted locally from **your own** compatible `OSUP.BIN`, using `scripts/prepare_osup.py`; available in the owner's private local media kit | Yes |
| `source-derived-synthetic-emmc.raw` | Owner-private source-derived synthetic eMMC, reconstructed from `emmc-data-extents.bin` with `reconstruct_media.py` | Yes for factory boot |
| `disposable-sd-2g.raw` | Disposable >=2GiB raw SD image, `truncate -s 2G disposable-sd-2g.raw` or media reconstruction script | Optional |
| `OSUP.BIN` | Your own firmware update; **not needed at runtime** once the ELF has been prepared | Only for extraction |
| `touch.txt` | Local text file containing physical electrode input; e.g. `0 0 0 800 1200` | Optional, for touchscreen |
| Linux dependencies | x86-64 Linux (Ubuntu 24.04 CI target), Python 3, Tkinter for GUI, compatible system libraries. `LD_LIBRARY_PATH` will use the bundle's `lib/` | Yes |

**No proprietary firmware, ROM extracts, decompilation, media extents, device credentials, screenshots or key material is in the public GitHub repo.** Keep the original firmware and generated media local. The supplied synthetic eMMC is **not** a complete factory device dump, so storage/ROM-verification tests may fail for reasons unrelated to QEMU.

## Fastest setup — owner-private Linux package

If you have the owner's `EXeSX-Linux-factory-run-kit.zip`, extract it and run:

```bash
unzip EXeSX-Linux-factory-run-kit.zip -d exesx-run
cd exesx-run
python3 reconstruct_media.py       # creates sparse 15.64 GB logical eMMC and disposable 2 GiB SD
chmod +x qemu/qemu-system-arm run_factory.sh
./run_factory.sh                    # original firmware + GUI floating keyboard
```

The compressed kit contains the latest compiled QEMU bundle, matching controller profile/helpers, extracted owner-provided A7 ELF, and packed media extents. Reconstructing media may consume substantial **logical** disk space; use a filesystem supporting sparse files. No standalone device dump or OSUP installer is required.

## Manual setup from CI and the original update

If you are obtaining the artifacts separately:

```bash
git clone -b experiment/dy357-m4-inputs-0804-20261023 \
  https://github.com/TheRainbowPhoenix/EXeSX.git
cd EXeSX

# Download and unzip the matching Linux CI artifact separately:
unzip /path/to/EXeSX-QEMU-latest-2026-10-28-Linux.zip -d /tmp/exesx-ci
tar -xzf /tmp/exesx-ci/exesx-qemu-linux-x86_64.tar.gz
mv exesx-qemu-linux-x86_64 qemu

# Prepare the owner-supplied ROM (unless an a7-bios-os.elf already exists):
python3 scripts/prepare_osup.py /private/path/OSUP.BIN -o ./a7-bios-os.elf

# The full source-derived eMMC is NOT generated by prepare_osup.py.
# Restore the owner's local emmc-data-extents.bin using reconstruct_media.py,
# or supply an already-prepared --emmc raw image.
python3 reconstruct_media.py
```

The above manual setup's final reconstruction command assumes you copied **both** `reconstruct_media.py` and `emmc-data-extents.bin` from the owner's private media kit into this directory; they are not public repository assets.

Launch the original factory UI:

```bash
python3 qemu/factory_control_panel.py \
  --elf ./a7-bios-os.elf \
  --emmc ./source-derived-synthetic-emmc.raw \
  --sd ./disposable-sd-2g.raw \
  --qemu ./qemu/qemu-system-arm \
  --profile ./qemu/profiles/imx7ulp-early-boot.ini \
  --tcg-thread single \
  --output-dir ./private/factory
```

If no desktop/Tk is available, add `--headless-check --check-mode menu --check-seconds 90`. The headless check prints observed original-firmware milestones; a time-out is a failed/unfinished attempt, not a factory pass.

## Factory menu input

The GUI's **TEST MENU** boot macro uses the real M4 physical key matrix:
1. Hold `0x9C + 0x90` across startup; release via the GUI worker's default ~4-second chord timing.
2. When the original version popup is waiting for a key, enter `0x93`, `0x93`, `0x94` with distinct press/release gaps.
3. Once the native TEST MENU paints, `0x91` navigates DOWN and `0x94` confirms a highlighted row. Avoid blind repeated ENTERs: key timing is imperfect and can select the wrong operation.

All keys are **physical input codes**, not synthetic A7 queue writes. Single-thread TCG (`-accel tcg,thread=single`) is the recommended startup default; multi-thread mode can exhibit different scheduling and keyboard timing. Always verify the original LCD before describing a menu or test as passed.

## Physical BU21029 touchscreen inputs and trace

```bash
printf '0 0 0 800 1200\n' > touch.txt

EXESX_BU21029_LPI2C_BUS=2 \
EXESX_BU21029_TOUCH_FILE="$PWD/touch.txt" \
EXESX_TRACE_BU21029=1 \
EXESX_TRACE_TOUCH_WORKER=1 \
./run_factory.sh
```

While the guest is running, a separate terminal may press/release the raw *electrode*:

```bash
printf '1 2048 2048 800 1200\n' > touch.txt  # down, raw X/Y, Z1/Z2
sleep 1
printf '0 0 0 800 1200\n' > touch.txt         # release
```

Valid X, Y, Z1, Z2 values are 12-bit raw ADC units, **not screen pixels**. The controller responds on original M4 LPI2C2 address `0x40`; physical PTB3/PORTB IRQ57 and M4 LPIT0 IRQ49 are controlled by the hardware model and original firmware. The binary's factory runner opts in to LPIT0 using `EXESX_EXPERIMENTAL_M4_LPIT0_IRQ=1`. Look in the private trace for the guest-issued `0x84` conversion read and `RX_REQUEST count=14`, and original A7 type `0x6000` messages. **Do not interpret a pen-IRQ/status read alone as a delivered touch event.** Touch test PASS is not established without a genuine original-ROM verdict.

Tracing can affect timing; run without trace variables as a negative/normal control.

## Direct headless QEMU (no Tkinter)

```bash
export EXESX_MEMORY_PROFILE="$PWD/qemu/profiles/imx7ulp-early-boot.ini"
export EXESX_EXPERIMENTAL_M4_BOOT=1
export EXESX_EXPERIMENTAL_MU_IRQ=1
export EXESX_EXPERIMENTAL_LPIT1_IRQ=1
export EXESX_EXPERIMENTAL_M4_LPIT0_IRQ=1
export EXESX_EXPERIMENTAL_LPTMR_IRQ=1
export EXESX_EXPERIMENTAL_LPTMR_PCS_CLOCKS=1
export EXESX_EXPERIMENTAL_M4_PORT_IRQ=1
export EXESX_EXPERIMENTAL_M4_TPM0_IRQ=1
export EXESX_EXPERIMENTAL_M4_TPM0_INPUT_MHZ=48
export EXESX_DIAGNOSTIC_A7_TPM6_KHZ=32
export EXESX_EXPERIMENTAL_LCD=1
export EXESX_EXPERIMENTAL_DMA1_M2M=1
export EXESX_USDHC1_EMMC=1
export EXESX_USDHC0_SD=1
export EXESX_USDHC0_SD_DETECT_GPIO=1
export EXESX_I2C4B_REGISTER_MIRROR=1
export EXESX_I2C40_REGISTER_MIRROR=1
export EXESX_SNVS_DIAGNOSTIC_SECURITY_PULSES=1
export EXESX_GPIOA_INPUT_MASK=0x808c6008
export EXESX_GPIOB_INPUT_MASK=0xc8
export EXESX_M4_KEY_MATRIX_FILE="$PWD/key.txt"
export LD_LIBRARY_PATH="$PWD/qemu/lib:${LD_LIBRARY_PATH:-}"
printf '0\n' > key.txt

./qemu/qemu-system-arm -machine exesx -m 64M \
  -accel tcg,thread=single -display none -serial none -monitor stdio -no-reboot \
  -drive "if=none,id=exesx-emmc,file=$PWD/source-derived-synthetic-emmc.raw,format=raw,snapshot=on" \
  -drive "if=none,id=exesx-sd,file=$PWD/disposable-sd-2g.raw,format=raw,snapshot=on" \
  -device "loader,file=$PWD/a7-bios-os.elf,cpu-num=0" \
  -d guest_errors,unimp -D ./qemu-trace-private.log
```

This direct launch **does not automatically press the boot chord or open the LCD GUI**. Use the factory helper above for that workflow. In HMP, `quit` exits QEMU.

**Storage safety:** both `-drive` arguments use `snapshot=on`. Never point factory FORMAT/WRITE/MEDIA FULL/RESET tests at real disks. Snapshot-on avoids persisting guest writes to those backing images, but it is not a substitute for a disposable test environment.
